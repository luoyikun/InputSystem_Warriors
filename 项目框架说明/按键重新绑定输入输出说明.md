# 按键重新绑定：输入到输出的变化过程

本文说明示例工程如何在运行时把一个输入动作从默认按键改为用户选择的按键，以及界面如何显示结果。

## 涉及组件

- 输入动作资源：`Assets/Input/InputActions_Player.inputactions`
- 重绑定组件：`Assets/Scripts/Behaviours/UI/UIRebindActionBehaviour.cs`
- 重绑定面板：`Assets/Scripts/Behaviours/UI/UIPanelRebindBehaviour.cs`
- 暂停菜单：`Assets/Scripts/Behaviours/UI/UIMenuBehaviour.cs`
- 玩家输入入口：`PlayerInput`，位于 `Player_Warrior` 预制体

场景中的重绑定条目通过 `actionName` 指定目标动作。当前场景能看到 `Attack` 这一项；按钮分别调用 `ButtonPressedStartRebind()` 和 `ButtonPressedResetBinding()`。

## 一句话概括

用户在 UI 按下“重新绑定”后，Input System 开始监听输入设备；捕获到有效按键后，把新控制路径写成目标 `InputAction` 的 **Binding Override**。之后同一动作由新路径触发，UI 也读取动作当前的有效路径并显示文字或图标。

## 输入与输出

| 阶段 | 输入 | 处理 | 输出/状态变化 |
|---|---|---|---|
| 打开暂停菜单 | 当前玩家触发 `TogglePause` | 菜单获取焦点玩家的 `PlayerInput`；刷新重绑定条目 | 每个条目知道当前要编辑哪个玩家、哪个动作，并显示当前绑定 |
| 请求改键 | 点击条目的重绑定按钮 | 调用 `PerformInteractiveRebinding()` 并开始监听 | UI 隐藏重绑定/重置按钮，显示“正在监听”状态 |
| 提供新输入 | 按下一个可接受的键或控制器按钮 | RebindingOperation 匹配输入并生成该 binding 的 override | Action 的 `overridePath` 更新，`effectivePath` 指向新控制路径 |
| 完成改键 | Input System 发出完成回调 | 释放 RebindingOperation，刷新绑定显示 | UI 恢复按钮，显示新按键的图标或可读名称 |
| 恢复默认 | 点击重置按钮 | 对目标 Action 调用 `RemoveAllBindingOverrides` | 移除该 Action 的 overrides，回到输入动作资源定义的默认绑定 |

## 详细调用链

### 1. 确定当前改哪个玩家的哪个动作

暂停菜单显示时，`UIMenuBehaviour.UpdateUIMenuState(true)` 调用 `UpdateUIRebindActions()`；该方法再调用 `UIPanelRebindBehaviour.UpdateRebindActions()`，逐个刷新面板上的重绑定组件。

每个 `UIRebindActionBehaviour.UpdateBehaviour()` 执行：

1. 通过 `GameManager.Instance.GetFocusedPlayerController()` 取得打开菜单的玩家。
2. 从玩家控制器取得 `PlayerInput`。
3. 用 Inspector 的 `actionName` 调用 `focusedPlayerInput.actions.FindAction(actionName)`。
4. 更新动作名称和当前绑定的 UI。

因此同一套菜单可以按当前焦点玩家显示/修改对应玩家的输入资源，而不是随意改某个全局玩家。

### 2. 从按钮开始监听

重绑定按钮的 OnClick 调用 `ButtonPressedStartRebind()`，接着进入 `StartRebindProcess()`。脚本先改变 UI 状态，再对 `focusedInputAction` 创建交互式重绑定：

```csharp
rebindOperation = focusedInputAction.PerformInteractiveRebinding()
    .WithControlsExcluding("<Mouse>/position")
    .WithControlsExcluding("<Mouse>/delta")
    .WithControlsExcluding("<Gamepad>/Start")
    .WithControlsExcluding("<Keyboard>/p")
    .WithControlsExcluding("<Keyboard>/escape")
    .OnMatchWaitForAnother(0.1f)
    .OnComplete(operation => RebindCompleted());

rebindOperation.Start();
```

这时输入来源是 Input System 识别到的键盘、鼠标、手柄等控制设备。被排除的输入不能成为新绑定：鼠标移动/位置不适合作为按钮，P 与 Gamepad Start 用于暂停，Escape 用于取消/返回。匹配后等待 0.1 秒再完成，以便组合输入有机会继续匹配。

### 3. 新输入如何改变 Action

假设 `Attack` 默认绑定在键盘 `E`，资源中的路径类似 `<Keyboard>/e`。用户在监听期间按下 `q`，Input System 会把对应 binding 的运行时 override 改为类似 `<Keyboard>/q` 的控制路径。

可以把数据关系理解为：

```text
改键前：binding.path        = <Keyboard>/e
        binding.overridePath = 空
        binding.effectivePath= <Keyboard>/e

改键后：binding.path        = <Keyboard>/e   （资源里的默认值保留）
        binding.overridePath = <Keyboard>/q   （运行时覆盖值）
        binding.effectivePath= <Keyboard>/q   （当前实际采用值）
```

这不是把 `.inputactions` 文件里的默认绑定永久改写，而是在当前 `InputAction` 实例上覆盖有效路径。因此之后输入 `q` 会触发原本的 `Attack` Action，`PlayerInput` 再按 Send Messages 通知方式调用 `PlayerController.OnAttack()`。玩家侧的攻击逻辑不必知道该动作来自 E、Q 还是手柄按钮。

### 4. 完成后 UI 如何显示新绑定

Input System 调用 `OnComplete` 后，`RebindCompleted()`：

- Dispose 并清空 `rebindOperation`；
- 显示重绑定与重置按钮，隐藏监听提示；
- 调用 `UpdateBindingDisplayUI()` 刷新绑定展示。

显示逻辑从 Action 的当前 control 找到 binding index，读取该 binding 的 `effectivePath`，再用 `InputControlPath.ToHumanReadableString()` 转为可读名称，并省略设备名。之后询问 `DeviceDisplayConfigurator` 是否有对应设备图标：

- 有图标：隐藏文字，显示图标；
- 没有图标：显示按键名称文字。

所以 UI 展示的是当前生效的路径，而不是单纯显示资源中的默认 `path`。

### 5. 重置如何输出回默认值

重置按钮调用 `ButtonPressedResetBinding()` → `ResetBinding()`。它执行：

```csharp
InputActionRebindingExtensions.RemoveAllBindingOverrides(focusedInputAction);
```

该调用移除目标 Action 上的所有 binding overrides，然后重新计算时 `effectivePath` 回到资源里的默认路径。脚本随后刷新 UI，显示默认绑定。

## 与资源中默认输入的关系

`InputActions_Player.inputactions` 定义默认 Action 和路径，例如：

- `Attack`：键盘 E、Gamepad South；
- `TogglePause`：键盘 P、Gamepad Start；
- `Movement`：WASD 复合绑定、Gamepad Left Stick。

重新绑定改变的是目标 Action 的 binding override。动作名与业务响应保持不变：`Attack` 仍对应 `OnAttack`，变化的是哪一个物理控制输入会触发它。

## 当前实现的范围与限制

- **运行时覆盖**：代码没有调用 `SaveBindingOverridesAsJson()`、PlayerPrefs 或文件写入接口，因此没有实现跨启动持久化。重新启动后是否保留不能由当前重绑定代码保证。
- **重置范围**：`ResetBinding()` 清除整个目标 Action 的所有 overrides；如果该 Action 有多个设备绑定，重置会一起恢复。
- **显示选择**：`UpdateBindingDisplayUI()` 使用 `focusedInputAction.controls[0]` 来找展示用 binding。它显示的是当前匹配到的一个 control，不是逐个列出所有设备绑定。
- **无可用 control 时**：代码直接访问 `controls[0]`。若动作没有解析出 control，显示更新可能发生索引错误。
- **设备/控制方案变化**：`PlayerController.OnControlsChanged()` 会对当前 Action Map 调用 `RemoveAllBindingOverrides()`，这可能清掉用户刚设置的运行时重绑定。
- **取消监听**：当前组件只处理完成回调，没有显式提供取消操作的入口。

## 调试时观察什么

1. 在 `StartRebindProcess()` 前确认 `focusedPlayerInput` 和 `focusedInputAction` 指向期望玩家/动作。
2. 重绑定完成后观察 `focusedInputAction.bindings`：默认 `path` 应保持，`overridePath` 应出现新路径，`effectivePath` 应等于新路径。
3. 按新键，确认 Input System 回调到对应的 `PlayerController.On<Action>()` 方法。
4. 按重置，再检查 `overridePath` 清空、`effectivePath` 回到默认路径。
5. 若界面名称或图标不更新，检查 `UpdateBindingDisplayUI()` 选出的 binding/control 以及 `DeviceDisplayConfigurator` 对应图标配置。
